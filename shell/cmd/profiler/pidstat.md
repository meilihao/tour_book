# pidstat
看每个进程的上下文切换

## example
```bash
pidstat -t -u 1
```

## 字段说明
- cswch/s = 自愿切换（等I/O、等锁）

    等锁、等I/O时会高

- nvcswch/s = 非自愿切换（时间片用完被抢占）

    时间片太短或进程太多时会高


一次上下文切换，内核到底做了什么？
1. 保存旧进程的上下文

    把当前进程的 CPU 寄存器（PC、SP、通用寄存器）保存到内核栈 → 写入该进程的 task_struct.thread 结构体 → 更新该进程的 task_struct 状态
    
1. 切换地址空间（最贵的一步）

    如果是进程切换：要切换页表（CR3寄存器），导致 TLB（地址翻译缓存）全部作废。后续每次内存访问都要重新走页表查询，代价是 数百到数千个CPU周期。
    如果是线程切换（同进程）：不需要切换页表，TLB 不失效，代价小得多

1. 切换内核栈和寄存器
    加载新进程的 task_struct → 恢复其寄存器现场 → 跳转到该进程的恢复路径

1. CPU Cache 污染

    新进程的数据不在 L1/L2 Cache 里，冷启动会导致大量 Cache Miss，间接拖慢每次内存访问

进程切换 vs 线程切换的代价对比
|对比项|进程切换|同进程线程切换|代价倍数|
|页表切换|✅ 需要（TLB失效）|❌ 不需要|5~10x|
|Cache污染|✅ 严重|⚠️ 较轻|2~3x|
|地址空间|完全独立|共享地址空间|—|
|单次切换代价|1~5 微秒|0.2~1 微秒|3~5x|

自愿切换 vs 非自愿切换：
1. 自愿切换（cswch/s 高）：进程主动调用 schedule() 让出CPU

    典型原因：等锁（mutex）、等I/O、等定时器、等pipe。这说明进程在"等事情"，等的是什么才是排查重点
1. 非自愿切换（nvcswch/s 高）：进程时间片用完，被内核强制抢占

    典型原因：进程太多、时间片设太短（Linux默认时间片由CFS动态计算，不是固定值）、CPU核数不够。这说明**CPU不够分**，是真的计算资源不足
